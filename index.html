Privacy policy

DMS Viewer - Version 1.0.1 - Applies to DMS Viewer 1.0.1; version 1.0.0 has no analytics

Bahasa Malaysia

This policy describes DMS Viewer's handling of report information in Microsoft Edge. The viewer is intended only for authorized users. This notice also informs individuals whose personal information may appear in reports. The extension is a local read/view tool, not a publisher-hosted report-processing service.

Authorized users and processing responsibilities

Users must be permitted to use the viewer and access the selected report library. The party deciding why and how source reports are processed may have controller responsibilities. The publisher's role depends on processing it actually determines or undertakes. Supplying software does not by itself establish processor status, and being an authorized user does not by itself determine all data-protection roles. Neither this policy nor acceptance transfers statutory responsibilities or grants access beyond existing permissions.

Information accessed and its sources

  • URLs entered by an authorized user, discovered PDF addresses, report names, folder paths and catalog labels.
  • Contents of selected PDFs. Reports can contain names, account identifiers, transactions, balances and other personal, financial or confidential business information.
  • The active tab URL only when the user selects Use current tab URL. The extension does not continuously monitor tabs or collect browsing history.
  • Display settings and a local record of agreement acceptance, including its version and acceptance time.
  • A random browser-installation ID and the signed offline license you enter, including its granted report IDs, user label, optional email address and any legacy issuance sequence number, license identifier, issue/start/expiry times, verification-key identifier and local verification-time checkpoint.

Sources are the URLs and controls users choose, the configured report library and selected reports. Reading and displaying information about identifiable individuals may be personal data processing even when access is restricted to authorized users.

Purposes and read/view-only operations

Information is used to discover reports, download selected PDFs, display and group records, calculate supported totals, retain viewer preferences and remember agreement acceptance. It is not used for advertising, marketing profiles, selling data or unrelated secondary purposes.

The extension accesses authorized reports for local viewing. The extension has no workflow to create, write to, edit, alter, overwrite, upload or delete source reports or remote account records, and it does not submit financial transactions. Grouping, filters, formatting and calculations affect only the local presentation. Browser host permission is broader than this read/view-only behavior and is not a separate read-only permission. Use a server-enforced read-only account if required by the applicable access controls.

Offline license information

The viewer generates a random installation ID locally; it does not read hardware serial numbers or create a hardware fingerprint. You may manually send the ID and an appropriate user label to your license issuer. The issuer signs a license for that installation and returns the key to you. The extension does not send the ID, license or reports automatically to an activation server and uses no online license-verification service.

The entered license is signed, not encrypted, and may identify its intended user. It is stored locally with the installation ID and verification-time checkpoint so it can be checked on later launches. Use a non-sensitive user label where possible. The issuer may retain information you voluntarily provide and copies of licenses outside the extension; use the issuer's privacy contact for information it actually holds. This is separate from the extension's automated processing.

A valid license is necessary to unlock report features. Invalid, mismatched or expired licenses leave the viewer locked. Removing the license through the License control removes the stored license but keeps the installation ID and other viewer data. Clearing extension storage or uninstalling removes retained extension data, subject to browser and organizational retention behavior.

Network access and recipients

Requests go directly from the browser to the configured report site using the user's existing sign-in. The extension does not request or store passwords. The report provider receives normal request information, which may include the IP address, requested paths and browser-managed authentication cookies. The provider's hosting, logs and authentication are subject to its own policies and the responsible organization's arrangements.

PDF parsing and calculations run locally with bundled libraries. The extension does not send reports, extracted tables, browsing data or credentials to the publisher, analytics services, advertisers or an external processing service. It contains no advertising. Version 1.0.1 offers optional analytics as described below; version 1.0.0 has no telemetry. If a user voluntarily contacts support, the submitted support information is handled through that selected channel, separately from the extension's automatic operation. Emails are kept internally for handling support or license requests. The mailbox provider handles email delivery and storage. Ding Lab keeps no separate support or licensing register. Do not include live client reports or credentials in public reviews or support requests.

Optional viewer usage analytics

In version 1.0.1, analytics is optional and requires a separate opt-in. If you opt in and analytics is configured, the extension sends one viewer_open event when a licensed viewer starts, with a random analytics-only client ID, to Google Analytics 4 through a Ding Lab relay hosted by Cloudflare. Cloudflare receives the ordinary request IP address as relay host. The event does not contain report contents, report URLs, license details or credentials. Analytics is used to understand viewer usage and improve the product. If analytics is not configured, no analytics is collected.

You can withdraw analytics consent at any time by clearing the “Share viewer-open counts with Ding Lab via Cloudflare and Google Analytics using a random analytics ID.” checkbox in the extension. Withdrawal stops future analytics events and deletes the local analytics ID; it does not delete events already received. Contact Ding Lab at dzwong97@gmail.com about analytics data requests. Analytics processing and retention depend on the relay and Google Analytics configuration.

Local storage, retention and security

Local browser extension storage retains the configured URL, discovered catalog URLs and labels, filters, theme, zoom, disclosure preferences, acceptance record, random installation ID and signed-license state. If analytics is enabled, an analytics-only client ID is also stored locally until consent is withdrawn or extension storage is cleared. Paths, labels and disclosure keys can include report or client identifiers. Users and responsible organizations should treat the device and browser profile as potentially containing sensitive information and apply appropriate access and retention controls.

PDF bytes and displayed report tables are held in memory while in use; the extension does not deliberately save their contents in persistent extension storage. Closing a report releases its viewer state. Reloading or unloading the panel clears that session; merely closing the side panel may leave the document in memory until the browser unloads it. Browser caching, operating-system memory and enterprise device policies are outside the extension's control.

Stored catalog entries and preferences remain until replaced, cleared or removed with extension data. The extension does not use browser sync storage or operate a publisher-controlled cloud account or report database. Local storage writes do not change source reports. There is no guarantee that local processing eliminates every security risk.

Browser permissions

  • sidePanel: display the viewer in the browser side panel.
  • storage: save the local catalog, preferences, acceptance record, random installation ID and signed-license state.
  • tabs: read the active tab URL when a user chooses to copy it.
  • HTTPS report-site access: retrieve report listings and PDF files from supported sites. The browser may describe this broader permission as reading and changing site data, although the current implementation only performs the report read operations described above.

No scripting permission is requested and no scripts are injected into websites. Use this URL? saves and uses the URL; it does not invoke a runtime browser permission request.

Choices and required information

Users may decline to use the viewer. Accepting the agreement is required to unlock it. A valid signed license for the local installation is required after agreement acceptance. A report URL, appropriate site access and the selected PDF are necessary for the corresponding report features; without them the report cannot load. Settings can be changed locally. Acceptance by an authorized user is not consent on behalf of report subjects and does not replace the responsible party's legal basis, notices or consent where required.

  • Clearing the URL removes that configured address, but does not erase all previous catalog entries or preferences.
  • Close reports or unload the panel to end the relevant viewing session, subject to the memory behavior described above.
  • Restrict site access, disable or uninstall the extension through Edge settings. Restricted access can prevent loading reports.
  • Clear extension storage using available browser tools or uninstall the extension to remove retained extension data, subject to browser and organizational retention policies.
